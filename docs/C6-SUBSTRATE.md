# C6 substrate report

## Decision

AeroSpace-as-backend is the recommendation, pinned to `v0.21.3-Beta` for the next controlled integration trial; do not ship it as validated until that trial passes. This is the newest tag cited by C6 and was confirmed as an official release (2026-07-16). The installed client/server are only `0.20.3-Beta` (`6dde91ba43f62b407b2faf3739b837318266e077`), and the server rejected commands while disabled in the original run. Enabling it alters machine-level behavior, so no agent did so; the captain later enabled it (see Evidence).

AeroSpace is lower-risk than a Chord-owned workspace model for the next milestone because its pinned release documents a public socket protocol and configurable empty keybinding tables, floating-window callbacks, and persistent workspaces. The repository already puts the backend behind a replaceable boundary. The alternative removes the external manager dependency but requires Chord to implement and maintain workspace/window control itself. This is a decision to evaluate AeroSpace, not proof its operational behavior passes.

## Evidence and gaps

- `aerospace --version`: client and server both report `0.20.3-Beta`, commit `6dde91ba43f62b407b2faf3739b837318266e077`.
- `aerospace list-windows --all ...`: in the first (original spike 6) run the server was disabled and responded “AeroSpace server is disabled and doesn't accept commands. You can use 'aerospace enable on' to enable the server”; no agent enabled it. The captain later enabled the server and re-ran spike 6 live: p95 53.497ms vs the 16.67ms budget, a FAIL that includes per-request CLI process spawn. It stays recorded as FAIL.
- The Unix socket `/tmp/bobko.aerospace-jjaguirr.sock` exists; its direct-socket (no-spawn) latency is spike 6b below.
- The exact pinned documentation/release inspected: [v0.21.3-Beta guide](https://github.com/nikitabobko/AeroSpace/blob/v0.21.3-Beta/docs/guide.adoc), [commands reference](https://github.com/nikitabobko/AeroSpace/blob/v0.21.3-Beta/docs/commands.adoc), and [release notes](https://github.com/nikitabobko/AeroSpace/releases/tag/v0.21.3-Beta). The guide describes empty fallback keybinding tables, `on-window-detected` floating callbacks, and `persistent-workspaces` config. It does not document a headless mode; no `headless` mention appears in the pinned guide. The release notes cite unrelated window-ID-zero and popup-detection fixes, not a latency guarantee.
- Socket-protocol source: [AeroSpace v0.21.0-Beta protocol discussion](https://github.com/nikitabobko/AeroSpace/discussions/2139) and the pinned command documentation. Spike 6 measures CLI request round trips (including process startup), not isolated socket transport time; spike 6b below measures the socket directly.
- Spike 6 failed on the captain Mac (p95 53.497ms vs 16.67ms) because it spawns the CLI per request. Probe 6b ([`spikes/socket-latency-direct.py`](../spikes/socket-latency-direct.py), closes #50, related #7) removes that: one persistent connection to `/tmp/bobko.aerospace-<USER>.sock`, 100 `list-windows --all --format %{window-id}` queries, same p95 budget. Wire format read from the installed commit `6dde91ba` (`Sources/AppBundle/server.swift`, `Sources/Cli/_main.swift`): bare JSON request `{"args","stdin","windowId","workspace"}`, bare JSON answer `{"exitCode","stdout","stderr","serverVersionAndHash"}`, no length prefix or handshake (0.21+ framing differs; the probe FAILs on it, so the result applies to installed 0.20.3, not the pinned release). **Result, run read-only on the captain Mac on 2026-10-17 with the server enabled: FAIL, direct-socket p95 41.322ms > 16.67ms (min 6.113, max 248.658, 100 samples).** Server-side latency, not CLI spawn, exceeds the budget (spike 6 CLI-spawn p95 53.497ms). Implication: AeroSpace reads are not viable per-frame; command-speed use only. A disabled server is reported as FAIL with the `aerospace enable on` remedy.
- No pinned-tag installation, configured-floating/no-key-binding run, or multi-window latency trial was possible here because only `0.20.3-Beta` is installed; the 6b result above therefore does not cover `v0.21.3-Beta`.
- Pinned wire format (read for #68 from the `v0.21.3-Beta` tag, `Sources/Common/util/NWConnectionEx.swift`, `Sources/Common/model/clientServer.swift`, `Sources/AppBundle/server.swift`): the client first sends `SOCKET_PROTOCOL_VERSION` (1) as a 4-byte little-endian integer and reads the server's; after that every message in both directions is a 4-byte little-endian length followed by that many bytes of JSON. The request carries `windowId` and `workspace` as explicit `null`s (the server adds a warning to `stderr` otherwise). This differs from the installed 0.20.3 described above. Only the framing was read from source and tested against a local server; it has not run against a live `v0.21.3-Beta` server.
- Permission checks succeeded where attempted; corresponding behavior probes were not run because controlled test apps, windows, and terminal sessions were absent. Vim-specific behavior in Terminal is manual and cannot be verified by the hotkey probe. No permissions or privacy settings were changed.
- AeroSpace is identified as MIT licensed by its [GitHub repository](https://github.com/nikitabobko/AeroSpace) (license at current default branch is `LICENSE.txt`).
- The source checkout lacks `docs/CHARTER.md` and `docs/ROLES.md`; see `docs/STATUS.md`.

## Required follow-up measurements

Per-probe results are tracked in [STATUS.md](STATUS.md); acceptance thresholds
and failure paths are listed in [`spikes/README.md`](../spikes/README.md).

Next trial: in a disposable macOS account, install and pin AeroSpace `v0.21.3-Beta`, configure empty AeroSpace key-binding tables, all windows floating via its new-window callback, and persistent workspaces; run all seven probes with the required fixtures/permissions already granted, and manually test Vim in Terminal. Record OS/build, app versions, permissions, sample sizes, thresholds, p95 timings, and failures. If headless operation cannot be achieved with the documented configuration, or if IDs/frames/latency fail the documented thresholds, reopen the substrate choice; do not paper over it with implicit window-size policy.

## Scope

This is a report of observed limits and a provisional recommendation, not a claim that C6 platform behavior passed. The harnesses are isolated under `spikes/` and are not product dependencies.
